Case study

Document Q&A

Upload a PDF, Word file, web page, or plain text and ask questions about that document. Answers stream back token by token, grounded in the retrieved passages and guarded so the document can never act as an instruction. Directed end-to-end, built with Claude Code, and shipped with a test suite and CI/CD.

Try it live View source

The problem

A RAG demo is not a document tool

Most retrieval-augmented generation examples are wired to one hardcoded article and one fixed collection. They show the technique but you cannot point them at your own file. This project turns that demo into a working service. You upload a document, it gets chunked, embedded, and indexed, and every question is answered from that specific document’s retrieved text, with the answer streaming back as it is generated rather than arriving in one block.

The build

Upload, retrieve, stream, log

An uploaded file is loaded by type, split into overlapping chunks with their start offsets recorded, embedded with OpenAI, and stored in a disk-persisted Chroma index. Each chunk gets a deterministic ID derived from its source and a content hash, so re-indexing the same document never creates duplicates. A question then runs through one of two retrieval strategies and the answer streams back over Server-Sent Events. Every question, answer, and the exact chunks used to produce it are logged to Postgres.

Upload→ Chunk + embed→ Retrieve→ Streamed answer

Two answering modes share the same pipeline. In chain mode, retrieval always runs before the model and the retrieved text is folded into the prompt inside a context block. In agent mode, retrieval is a tool the model chooses to call, so a follow-up that needs no lookup skips it entirely.

My role

Directed end-to-end, built with Claude Code

  • Directed the architecture: typed settings read from the environment, one loader per file type, an indexing layer with deterministic chunk IDs, and an answering layer that keeps the API, CLI, and web UI on a single shared code path.
  • Made the call to treat every retrieved passage as untrusted data. Both answering modes wrap the context in an explicit instruction to ignore anything inside it that reads as a command, so an uploaded document cannot hijack the model.
  • Built the streaming layer for both modes, pulling tokens and retrieved sources from LangChain’s event stream in agent mode and from combined message and value streams in chain mode.
  • Hardened it for production in an AI pair-programming session with Claude Code: an offline test suite covering config parsing, loaders, chunking, the CLI, and logging, plus a GitHub Actions pipeline running ruff and pytest on Python 3.11 and 3.12 and building the Docker image.
  • Packaged the whole thing with Docker Compose so the app and its Postgres database come up together identically anywhere.

Technical highlights

LayerDetail
IngestionPer-type loaders for PDF (pypdf), DOCX (python-docx), HTML, and plain text, each tagged with a readable source name and guarded against empty files
ChunkingRecursiveCharacterTextSplitter, 1000-character chunks with 200 overlap, start index recorded on every chunk for stable IDs
RetrievalOpenAI text-embedding-3-small over a disk-persisted Chroma collection, top-k similarity search
AnsweringLangChain create_agent, chain mode via a before_model middleware, agent mode via a retrieval tool, both grounded-only and prompt-injection-guarded
StreamingServer-Sent Events endpoint, token by token, with a done event and inline error frames
LoggingPostgres via SQLAlchemy Core, no ORM, a JSONB column holding every retrieved chunk, silently skipped when no database is configured
DeliveryDocker and Docker Compose (app plus Postgres), one entrypoint routing CLI subcommands or the API server
CI/CDGitHub Actions running ruff and pytest on Python 3.11 and 3.12, a Docker image build, and publish to GitHub Container Registry on main
